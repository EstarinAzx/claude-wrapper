Slice 2 of spec #120.

## Do

Give fenced code blocks in assistant output a copy button.

## The mechanism, and the one thing that is genuinely undecided

`markdown.css` **cannot** deliver this — react-markdown owns the markup, so CSS there can only ever be descendant rules. The button must come from a **`components` override** on `ReactMarkdown` (replacing the `pre` renderer). Note there is **no in-repo precedent**: `grep -rn "components=" src/` is empty repo-wide, and `Chat.tsx` currently passes only `remarkPlugins` and `rehypePlugins`. You are establishing the pattern — keep it minimal, and apply it on both render paths or state why only one.

**The clipboard route is NOT decided, and must not be guessed.** Spec #120 records why:

- `src/main/index.ts:376-379` — dev loads `ELECTRON_RENDERER_URL` (http://localhost); **production loads `win.loadFile()`, a `file://` URL**.
- **No `setPermissionRequestHandler` is registered anywhere** in main, so Electron's defaults apply unexamined.

So a button written against `navigator.clipboard.writeText` can pass jsdom, pass `npm run dev`, and be **inert in the built app**. That is #117's *a callable route is not an effective one*, sitting in the one place review does not look.

**Measure first, then pick.** Verify in the BUILT app (`npm run build` plus a `run-desktop` driver), not in dev and not in jsdom. Two routes are open, and the earlier reading that ruled one out was wrong:

1. `navigator.clipboard.writeText` — no new surface at all.
2. An `ipcRenderer.invoke` bridge to main's `clipboard` module. **This does NOT require an ADR** — the sandbox ADR's requirement is triggered by preload needing **Node**, which an invoke bridge does not.

Prefer (1) if it demonstrably works in the built app. Fall back to (2), or to a hidden-textarea `document.execCommand('copy')`, only on evidence. **Record which route you took and the evidence in a ticket comment.**

## Constraints

- Model output is on record as **hostile input** (`.context/decisions/2026-07-31-the-renderer-is-sandboxed-and-the-driver-must-not-undo-it.md`). Copy the block's **text content**, never anything interpreted, and never route it through an `innerHTML` path.
- The renderer runs `sandbox: true`. Do not undo it. Do not add `nodeIntegration`.
- The button is an icon button: per `.context/decisions/2026-08-04-the-focus-ring-is-picked-per-control-not-applied.md`, **every icon button takes the hairline focus ring alone** (`inset 0 0 0 1px var(--tint-6)`), never the shared focus group's wash — a wash on a control that already paints a fill reads as a second hover state.
- Styles belong in `markdown.css`, never in `shared.css`.
- No comment in any stylesheet may contain a closing brace, and no scrollbar rule may be component-scoped.

## Acceptance

- [ ] Every fenced code block in an assistant message carries a copy control; inline `code` does not.
- [ ] Clicking it places the block's exact text on the clipboard **in the built app**, demonstrated by a `run-desktop` driver, not by a unit test alone.
- [ ] The control gives confirmation feedback and returns to rest.
- [ ] Keyboard reachable, with the hairline focus ring.
- [ ] The chosen clipboard route and its evidence are recorded in a ticket comment.
- [ ] `npm test` / `typecheck` / `build` green.
