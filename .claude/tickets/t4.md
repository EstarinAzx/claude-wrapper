Slice 4 of spec #120.

## The measurement that authorises this ticket

`scripts/recon-120-command-surface.mjs`, zero CLI turns:

- `/effort` **is** advertised by the CLI — `description: "Set effort level for model usage"`, `argumentHint: "<low|medium|high|xhigh|max|ultracode|auto>"`.
- The model list carries **`supportsEffort`**, **`supportedEffortLevels`**, `supportsAdaptiveThinking`, `supportsAutoMode`, `supportsFastMode`.
- **14 of 15** models report `supportsEffort: true`.
- `supportedEffortLevels` union = **`["low","medium","high","xhigh","max"]`**.

And from the SDK's own typings:

- `sdk.d.ts:553` — `export declare type EffortLevel = 'low' | 'medium' | 'high' | 'xhigh' | 'max';`
- `sdk.d.ts:1664` — `effort?: EffortLevel`, on the **`Options`** type declared at `:1322` — the same object `model` and `resume` live on.

## Do

A five-position effort control in the composer, beside the model pill.

**Five positions, not seven.** `ultracode` and `auto` appear in the command's argument hint but in **neither** the SDK's `EffortLevel` **nor** any model's `supportedEffortLevels`. They are modes, not points on an ordered scale, and inventing a slider position for them is the guess this repo forbids. Recorded as an owner call in `.claude/vibe.md`.

## Shape, and the two facts that determine it

**1. The levels come from the CLI, never from a hardcoded array.** This is #53's rule for the model list and it applies unchanged: read `supportedEffortLevels` off the model entries that `model:list` already returns. If the app's `ModelInfo`/`ModelOption` types currently strip those fields, widen them — that is part of this ticket.

**2. Changing effort must discard and rebuild the engine.** `effort` rides `Options`, and Options bind at query **CONSTRUCTION** (#73 — `resume` binds there and `ensureQuery` returns early ever after). A setter that only stores the value will appear to work and change nothing. Follow `model:set` at `src/main/index.ts:721` **exactly**:

- `isTrustedIpc(event)` guard first.
- Validate by **membership in the five-value set** — compare, never coerce (`src/shared/backdrop.ts` is the pattern; `String(value)` would admit anything that stringifies).
- Store the pick in a small module mirroring `src/main/model-mode.ts` (78 lines), exposing the query-options fragment the way `toModelOptions` does.
- `discardEngine(engine?.sessionId() ?? pendingResume)` — **read the resume target BEFORE the discard**, so the pick keeps the conversation.
- Broadcast the resolved value so the control re-renders.

**3. Handle the model that does not support effort.** One of fifteen reports `supportsEffort: false`, and `supportedEffortLevels` may be absent or short. The control must degrade honestly — disabled or hidden with a reason — never silently send a level the current model rejects.

## Constraints

- **This is not a slash-command wrapper.** The dumb-pipe rule forbids the renderer parsing or validating commands; this ticket does not send `/effort` as text, it sets a query option. Do not add renderer-side command handling.
- A pill click discards the engine, and #112 made the two list reads rebuild lazily. Verify the effort control still reads its levels after a discard — `ensureListEngine` is the read path.
- The control is disabled while a turn streams, as the model pill is.
- Focus treatment per `.context/decisions/2026-08-04-the-focus-ring-is-picked-per-control-not-applied.md`: a control that paints a fill in any state takes the hairline alone.
- New styles go in `composer.css` (or `appearance.css` if it lands in the dock), never in `shared.css`.

## Acceptance

- [ ] A five-position control sets effort, and the positions come from the CLI's `supportedEffortLevels`, not a literal array.
- [ ] Setting effort rebuilds the engine and **keeps the conversation** (resume target read before the discard).
- [ ] A driver or harness demonstrates the setting actually reaches the SDK — a stored value that never reaches `Options` is the failure mode this ticket exists to avoid.
- [ ] A model reporting `supportsEffort: false` degrades honestly and visibly.
- [ ] The IPC payload is validated by membership, and a hostile payload is rejected without coercion; a test asserts the engine was never reached on rejection.
- [ ] Disabled while busy.
- [ ] `npm test` / `typecheck` / `build` green.
