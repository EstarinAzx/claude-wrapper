Slice 3 of spec #120.

## Read this before designing — the obvious implementation is impossible

The owner asked to "redit message, resend". **A true edit cannot persist**, and this is measured rather than argued:

`src/renderer/src/useChat.ts` — `setMessages(transcript.map(toChatMessage))`. Both `adoptSession` and the live-tail reload loop replace the **entire** `messages` array from `loadTranscript(id)`. The renderer's list is a **projection of the disk transcript**, which the CLI owns. Any renderer-side edit to an already-sent message is erased by the next adopt or tail reload, and the superseded turn stays in the conversation regardless.

`/rewind` is **not** among the CLI's 121 advertised commands, so there is no history-rewriting route to lean on either — slice 7 measures whether any exists at all.

## Do

Ship the honest shape: **refill the composer from a past user message.** A user message gains an affordance that puts its exact text back in the composer, where it can be edited and sent as a **new** turn.

Do NOT mutate `messages`. Do NOT delete or visually rewrite the original turn.

## Constraints

- **`InputBar` is never disabled while a turn runs** (#80), and `useChat.send` is the ONE place that refuses a send while busy. Refilling during a turn must interact correctly with the queued-send commitment — that commitment is a **boolean flag on the draft**, not a copy of it, so a refill must not create a second draft or double-commit.
- **Workspace-scoped composer state is reset by the `key={cwd}` remount**, never by hand from `App` (see `InputBar.tsx`'s `pendingInsert` comment). Anything added to the composer inherits that reset — do not add a manual clear to `switchWorkspace`'s `ok` branch.
- **`.bubble` and `.message-input` must stay ungrouped in CSS** and no comment may carry a closing brace — `tests/multiline-composer.test.tsx` reads the stylesheet as raw text.
- The only text normalization on the send path is `useChat.ts`'s `raw.trim()`. Do not add another.
- A user message may carry attachments and `attachmentMarkers`. Decide and **state** whether refill restores text only. Text-only is acceptable and is the smaller diff — but say so rather than leaving it ambiguous.
- The affordance must not add a tab stop to every message row unconditionally if that would flood the rail's ~100 existing stops; prefer a control revealed on hover/focus of its own row, still keyboard reachable.

## Acceptance

- [ ] A past user message can be put back into the composer, edited, and sent as a new turn.
- [ ] The original message is unchanged in the pane and unchanged on disk.
- [ ] A refill followed by a live-tail reload neither loses the draft nor duplicates the message.
- [ ] Refilling while a turn is streaming behaves correctly against the queued-send commitment.
- [ ] Whether attachments are restored is decided, implemented and stated.
- [ ] Keyboard reachable with the correct focus treatment for its control type.
- [ ] `npm test` / `typecheck` / `build` green.
