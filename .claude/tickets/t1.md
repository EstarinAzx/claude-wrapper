Slice 1 of spec #120.

## The premise is already measured — do not re-litigate it

`remark-gfm` is **already wired** on both markdown render paths (`Chat.tsx:132` assistant, `:146` command), alongside `rehype-highlight`. GFM tables therefore already parse into real `<table>` DOM today.

`src/renderer/src/styles/markdown.css` is 116 lines and contains **zero** table rules — no `table`, `thead`, `tbody`, `th`, `td`. That is the whole defect: tables render, unstyled, as run-together text.

**This is a CSS ticket.** Do not add a plugin, do not touch `Chat.tsx`, do not add a dependency.

## Do

Add table rules to `markdown.css` so a GFM table reads as a table in the Frost Mono system: header separation, cell padding, alignment honoured (`remark-gfm` emits an `align` style on cells), and a sane result when a table is wider than `.chat-column`'s 760px.

## Constraints, each with a reason

- **Descendant rules only.** react-markdown and highlight.js own the markup; nothing can be *added* to the output from this file. `markdown.css` says so itself: *"Both own their own markup, so these can only ever be descendant rules."*
- **Do not add an `@import` or reorder `styles.css`.** The import order IS the cascade (`.context/decisions/2026-07-30-the-import-order-is-the-cascade.md`). `markdown.css` already sits after `tokens`/`themes`/`base`/`shared`, so adding rules inside it is safe; moving lines is not.
- **No scrollbar rule may be scoped to a component.** `tests/scrollbar.test.ts` reads the whole `styles/` directory as raw TEXT and fails a scoped `::-webkit-scrollbar*` selector. The global rule in `base.css` already covers overflow — do not author a new scoped one.
- **No comment in this file may contain a closing brace**, for the same raw-text reason.
- Use existing tokens. No new colour literal unless `tokens.css` genuinely lacks one — and say so in the ticket comment if it does.
